# 课小伴 —— 共享课表微信小程序

> 不是「又一个日历」，而是面向班级与小组的课程协作工具。

## 项目定位

在电子课表的基础上引入两条差异化主线：**共享课表与空闲时间对齐**、**AI 智能建表**（对话 + 图片双入口），并以**节假日自动识别**为支点，把「不提醒」做成一个可解释的功能。

## 快速开始

1. **打开项目**：微信开发者工具 → 导入项目 → 选择本项目目录 `C:\Users\email\Desktop\kexiaoban`
2. **配置 AppID**：在 `project.config.json` 中把 `appid` 换成你自己的小程序 AppID
3. **配置云环境**：在 `miniprogram/config.js` 中填入 `CLOUD_ENV_ID`，并把 `USE_CLOUD` 改为 `true`
   - 未配置云环境时，项目自动降级为本地存储模式（`wx.storage`），可完整开发调试
4. **建数据表**：云数据库中创建 `timetables`、`courses`、`profiles`、`relations` 四张表，启用行级安全策略
5. **运行测试**：`node test/run.js`

## 核心算法

### 1. 课程展开（`logic/course-expand.js`）

把每门课展开为「周次 × 星期 × 节次」的三维占用点集：

```
P = 空集
for 每个属于周次规则 w 的周次 week:
    for i 从 0 到 n-1:
        将 (week, d, s + i) 加入 P
```

> ⚠️ **关键陷阱**：若忽略周次维度，直接按「星期 + 节次」计算，会把单双周课程误判为每周占用 —— 「找搭子」会把可用空档算没。

### 2. 空闲对齐（`logic/free-align.js`）

用户占用集的补集即空闲集，两人空闲集取交集即共同空闲。连续空闲格合并为时段，按周次分组输出。结果以「第 N 周 周X 第 a-b 节」呈现，而非笼统的「有时间」。

### 3. 免打扰判定（`logic/dnd-rule.js`）

六步固定优先级，命中即返回：

| 优先级 | 条件 | 结果 |
|---|---|---|
| 1 | 法定节假日 | 不提醒（最高） |
| 2 | 自定义不提醒日期 | 不提醒 |
| 3 | 落入免打扰时段 | 不提醒 |
| 4 | 调休补课日 | 正常提醒 |
| 5 | 该课程单独静音 | 不提醒 |
| 6 | 其他情况 | 正常提醒 |

> ⚠️ **核心风险**：第 1 步与第 4 步的顺序。调休意味着「周六上周一的课」与「工作日在放长假」同时存在，必须依靠**日期精确匹配**，禁止用「周末 / 工作日」的粗粒度规则替代。

## 课表页交互

课表页采用「角格选周 + 手势切周 + 自动定位今天」的交互方式：

| 交互 | 说明 |
|---|---|
| **当前课表条** | 顶部显示当前课表名 + 「共 N 周 · 起止日期」，点击进入课表管理（新建 / 切换 / 改开课时间与周次） |
| **自动定位今天** | 打开即按今天定位到对应周次，表头「今天」高亮并画圆点，所在列淡色底 |
| **当前时间指示线** | 查看本周时，在今天的列上画一条横线 + 时刻标签，每分钟自动推进 |
| **回到今天** | 底部按钮（仅查看非本周时出现）+ 周次面板顶部按钮，**带动画**跳回本周 |
| 左上角角格 | 显示「第X周 · 单/双」，点击弹出周次选择面板；**本周**单独描边 + 角标；查看非本周时角格降饱和 |
| 左右滑动网格 | 切换上一周 / 下一周。**跟手位移 + 松手回弹/切页动画**，支持快速滑动（fling） |
| 下拉刷新 | 只重新拉取课程数据，**不改变**当前浏览的周次（回今天是底部按钮的职责） |
| 节次列 | 显示大节序号 + 完整时间段（如 `08:00` / `09:35` 两行，一个大节 95 分钟） |
| 午休 / 晚休 | 在网格中插入分隔带，不参与课程占用计算 |
| 点击课程块 | 弹出详情卡片（时间、节次、周次、教师、地点） |

> 节次设置的入口只有一个：**「我的 → 节次设置」**。课表页底部不再重复放置该入口，避免同一功能两个入口。

### 自动定位与当前时间（`utils/week.js`）

课表的「今天」由**当前课表自己的** `term_start_monday`（第 1 周周一）推算，不依赖任何在线接口：

| 函数 | 作用 |
|---|---|
| `currentWeekOf(termStart, today?, maxWeek?)` | 今天属于第几周，自动 clamp 到 `[1, maxWeek]` |
| `todayPosition(termStart, today?, maxWeek?)` | 返回 `{ week, dayOfWeek, inTerm, date }`，`inTerm=false` 表示今天不在学期内 |
| `isToday(termStart, week, dow, today?)` | 判断某个 (周次, 星期) 是不是今天，用于高亮 |
| `currentTimeStr(date?)` | 当前时刻 `"HH:MM"`，供指示线使用 |
| `daysBetween` / `startOfDay` / `weekdayOf` | 按本地日历天计算差值、归一化、星期换算 |

**职责划分**（这是本页交互的核心约定）：

| 触发点 | 行为 |
|---|---|
| 首次进入 | **直接**定位到本周（界面尚未呈现，无需动画） |
| 点「回到今天」 | **带动画**跳回本周；已在当周时播放一次强调回弹 |
| 下拉刷新 | **只刷数据**，不改变当前周次 |
| `onShow` 回到前台 / 定时器跨天 | 只刷新 `todayWeek / todayDow / inTerm`，**绝不**改变用户正在浏览的周次 |

已定位到本周、或今天不在学期内时，底部「回到今天」按钮**不显示**，避免无效操作。

**回到今天的动画逻辑**：方向由「目标周在当前周的哪一侧」决定，符合直觉——目标在右侧（周次更大）则内容向左滑出、目标从右侧滑入，反之亦然。跨多周时不逐周播放（那会花很久），而是一次性滑出 → 换数据（无动画定位到反向另一侧）→ 滑入居中，共 3 帧。滑出时长随跨度略增（200ms 起，每多一周 +30ms），上限 320ms。

**当前时间指示线**：把当前时刻与每一节的起止时间比对，换算成像素偏移——落在课内按进度线性插值，落在休息段按休息行插值，早于第 1 节贴顶、晚于最后一节贴底。定时器每 60 秒刷新一次。

### 滑动动画实现

采用 CSS `transform: translate3d` 驱动，不触发重排，性能开销低：

1. **触摸开始** → 关闭 transition，保证跟手零延迟
2. **触摸移动** → 横向分量更大（`dx > dy`）即接管手势，避免与纵向滚动冲突；边界处做阻尼（×0.35），超出 120px 后衰减
3. **松手** → 位移超 40px、或快速滑动（fling，速度 ≥ 0.5px/ms）触发翻页（滑出 → 换数据 → 滑入，共 3 帧）；未达阈值则回弹归位

## 多课表

支持建多张互不干扰的课表，典型场景：本学期 / 下学期并存、主修 / 辅修并存。

### 数据模型

新增 `timetables` 表存课表元数据，课程通过 `timetable_id` 归属到某张课表：

```
timetables
  id                  自增主键（本地为 number，云模式为 _id）
  name                课表名称，如「2026 秋 主修」
  term_start_monday   第 1 周周一日期 "YYYY-MM-DD"，周次→日期换算的基准
  total_weeks         学期总周数（1 ~ 30）
  is_current          是否为当前课表（全局唯一 only one true）
  created_at          创建时间戳

courses
  …（原有字段）
  timetable_id        所属课表 id（★ 新增，用于隔离不同课表的课程）
```

### 关键约束（由 `api/timetable.js` 保证）

| 约束 | 实现 |
|---|---|
| `is_current` 全局唯一 | `setCurrent()` 先把其它课表全置 `false`，再置目标为 `true` |
| 取当前课表有三级回退 | 本地缓存 id → `is_current` 标记 → 列表第一张，保证总能拿到可用结果 |
| 删除课表**级联删课程** | `removeTimetable()` 先删该课表下所有课程，再删课表本身 |
| 当前指针自动转移 | 删掉当前课表后，指针挪到剩余第一张；无剩余则清空缓存 |
| 首张课表自动设为当前 | `addTimetable()` 检测到是唯一一张时自动 `setCurrent` |
| 总周次与日期校验 | `clampTotalWeeks()` 夹紧到 `[1, 30]`；`normalizeTermStart()` 校验 `YYYY-MM-DD`，非法则回退 config |

### 数据迁移（幂等）

本次改动之前的课程没有 `timetable_id` 字段。若不迁移，用户升级后会看到**课表一片空白**——数据还在但显示不出来。

`ensureDefaultTimetable()` 承担这个职责：

1. 没有任何课表 → 按 `config.TERM_START_MONDAY` / `DEFAULT_TOTAL_WEEKS` 创建「我的课表」
2. 已有课表 → 补齐当前指针
3. 把 `timetable_id == null` 的历史课程挂到当前课表下

由 `kxb:migrated_multi_timetable` 标记保护，**只执行一次**。课表页 `onLoad`、课表管理页、建表页都会调用它，谁先进来都能兜住。

### 页面职责

| 页面 | 职责 |
|---|---|
| `pages/timetable-manage/` | 新建（名称 / 开课日期 / 总周次）、切换当前、编辑、删除（含课程数提示） |
| `pages/timetable/` | 读当前课表的 `term_start_monday` + `total_weeks`，替换原先的硬编码 config；`onShow` 比对 id，变了就整页重载并回到今天所在周 |
| `pages/profile/` | 「我的课表」卡片显示当前课表名 / 课程数 / 总周次 / 课表张数，点击进管理页 |
| `pages/build/` | 新增课程前兜底调用 `ensureDefaultTimetable()`，保证课程有归属 |

### 找搭子的特例

`listCoursesByOwner()` **不按** `timetable_id` 过滤 —— 朋友的课表 id 与本地无关，找搭子关心的是「对方全部课程造成的占用」，跨课表合并才符合语义。

## 自定义节次

「我的 → 节次设置」可调整每天的上课节次，适配不同学校作息：

| 配置项 | 说明 |
|---|---|
| 上午 / 下午 / 晚间节数 | 各时段上几个大节（可设为 0 表示该时段无课） |
| 第 1 节开始时间 | 每个时段的起始时刻 |
| 每节时长 | 大节时长 45 / 90 / 95 / 100 分钟（默认 95，即两小节 + 5 分休息） |
| 课间休息 | 两大节之间的间隔（默认 20 分钟） |

设置后时间轴自动重算（如上午 2 个大节 = 08:00 起，每节 95 分 + 课间 20 分，第 1 节 08:00-09:35、第 2 节 09:55-11:30）。

**越界处理**：若已有课程排在新范围之外，保存前会列出受影响的课程并要求确认，保存时自动裁剪，不会静默丢数据。

配置存储在 `utils/schedule.js` 的 `SCHEDULE_STORAGE_KEY`，默认值定义在 `config.js`：

```js
SCHEDULE: {
  segments: [
    { key: 'morning', label: '上午', slots: 2, startFirst: '08:00', duration: 95 },
    { key: 'afternoon', label: '下午', slots: 2, startFirst: '14:00', duration: 95 },
    { key: 'evening', label: '晚间', slots: 2, startFirst: '19:00', duration: 95 }
  ],
  breakWithinSegment: 20,
  segmentBreaks: [
    { afterKey: 'morning', label: '午休' },
    { afterKey: 'afternoon', label: '晚休' }
  ]
}
```

> 节数不写死，是为了给后续「拍照识别课表」留出空间 —— 不同学校作息差异很大，识别结果需要能落到任意节次结构上。

### P1 · AI 对话建表（M4 → v1.1.0）

**现状**：`pages/build/index.js` 的 `parseByAI()` 目前是**本地规则解析**（按标点切句 + 正则抽字段），只是骨架；预览确认页已具备。

**要做**（对应 Step 12 + Step 13）

1. **Step 12 统一解析管线**：`预处理 → 调用大模型（流式）→ Schema 校验 → 统一预览确认页 → 批量写库`
   - 关键设计：**对话建表与图片识别不是两个功能，而是同一条管线的两种输入形态**，在「结构化课程 JSON」这一步汇合，共用校验与预览页 —— 这是代码复用率与答辩加分点
2. **Step 13 AI 对话建表**：把 `parseByAI` 替换为云服务大模型**流式**调用
   - **必须走流式**：后端网关对非流式请求会直接拒绝；且能让用户实时看到解析进度
   - 约束模型输出固定字段 JSON（课程名 / 星期 / 开始节次 / 节次数 / 教师 / 地点 / 周次），无法识别的字段返回**缺失标记**而非猜测填充
   - 三类容错：解析为空 → 提示更具体的说法；字段缺失 → 预览页标记待补；网络 / 模型异常 → 提供「转手工录入」出口

**验收（M4）**：一句话可生成多门课程，且在预览页可逐条修改。

**波及文件**：`pages/build/index.js`（替换 `parseByAI`）、`api/`（新增 AI 调用封装）、`pages/build/index.wxml`（流式进度展示）

### P2 · 图片识别建表（M5 → v1.2.0）

**现状**：完全未实现。

**要做**（对应 Step 14 + Step 15）

1. **Step 14 图片入口**：建表页新增「拍照导入」标签 → 压缩至长边 1600px 内 → 转 base64 → 上传对象存储 → 汇入 P1 的解析管线
   - 隐私：图片仅用于本次识别，保留 `IMAGE_RETENTION_DAYS`（默认 7 天）后自动清理，用户可手动删除
   - 界面须如实提示各来源的识别预期（教务系统截图高 / 纸质拍照中 / 手写低）
2. **Step 15 网格还原算法（本项目最难的技术点）**：六步管线
   `网格定位 → 文字提取 → 坐标映射 → 文本切分 → 冲突消解 → 输出结构化列表`
   - **必须截入表头**：没有「周一…周日」与「第 1…12 节」这两行，坐标映射就无从建立
   - **第 5 步冲突消解最容易出错**：一门跨两节的课在网格上占两个格，逐格输出会把它拆成两条记录 —— 必须做合并判断；而同一时段确实有两门课（单双周交替）时又不能合并

**验收（M5）**：一张教务系统截图可正确识别为结构化课程列表；含跨节课程时为一条记录而非两条。

**依赖**：P1 的解析管线必须先落地，否则要写两套。
